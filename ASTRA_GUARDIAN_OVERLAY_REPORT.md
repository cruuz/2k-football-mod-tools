## Decisions and PROVED executable behavior

The record map is now unambiguous within the studio: +0x52 bits 0..4 are depth
locks, bits 5..7 are Speedster/Right-Stick/Juke. At +0x53, bit 0 is Star Tag,
bits 1..4 are Spin/Truck/Hurdle/Stiff-Arm, and **bit 5 (0x20) is Guardian cap**.
Bits 6..7 remain unassigned. The abilities word mask `0x1EE0` excludes the new
word mask `0x2000`; every owner writes a mask. The standalone exhaustive
256-byte test verifies adjacent-bit preservation. The current record codec
stores the cap as `unknown_53_high & 0x10`; Rosters derived-property, bulk and
CSV wiring is reserved to that parallel owner in WIRING.md.

The brief's 336-byte bitmap/cache allowance is **not consumed**. A persistent
record bit supplies selection directly, and native lookup supplies the current
resource each time. There is no player-index identity bitmap, persistent texture
pointer, auxiliary allocation or write into `.text`. Actual request:
`('nfl2k5_guardian_overlay', 'code', 496, 16)`, within the 2,048-byte RX budget.
The existing v3 allocator provides all new space; its page layout is unchanged.
This frees the entire planned 336-byte RW allowance.

| `0x8FB45` | `0F B6 8B 1F 53 B6 00 3B C1` | The existing B comparison before shine calculation. B refreshes and continues at `0x8FBB1`; other materials replay the comparison at `0x8FB4E`. |

**PROVED:** full dependent native spans are SHA-256 pinned, normalizing only
owned hook bytes. Correctly repinned tampered code, hook, configuration and
helper spans refuse. Requests are sealed before installation; a missing request
in an already-grown union refuses. Replaying preserves installed practice
settings; an explicit different setting requires a supported-base rebuild.

**PROVED:** refresh accepts only low/high LOD 0/2, an in-range cached B slot
whose material name is exactly `HI_HELMET_B`, and a native player context in
`[0xB652D0]`'s stride-0x54 array bounded by `[0xB65274]`. It checks record/context
identity, normal/headful context flags, render-entity record identity and raw
helmet selector 0/1. Standalone preview contexts fail array membership. The
slot is hidden and its old texture/reflection cleared before a new decision.
Mode is read fresh from `0xE5FF80`: unsigned 0..3 enables the practice override;
other modes require the saved individual bit. No practice decision writes the
roster record. Missing/invalid context, record, selector or texture cannot
turn B on.

**PROVED:** native `0x449E0`/`0x443D0` resolves global `helmet01`; native
`0x8E3F0` enables and binds only B. The later native material iteration refreshes
B, keeps reflection pointer +0x34 and byte +9 zero, and skips B's retail shine
calculation. Mode/record/texture changes are therefore reconsidered on updates,
including when the same material/scene address is reused. No own cache survives
resource-group release. B accessories remain disabled; A/C, facemasks and
visors are handled by their original routes.

**PROVED:** bounded tests execute the **complete retail equipment binder** for
both A/C families, both LODs and no/clear/dark visor, then the actual hook.
They assert the ordinary chosen shell stays enabled and every non-B material
byte remains identical. They also test flagged/unflagged players, all practice
modes, explicit override off, missing texture, simulated group release and native re-registration,
invalid selector, headless/preview context, stale material identity, late matte
refresh, register/flag/stack preservation and masked clone behavior. Native
lookup, registration/relocation and material helpers run their retail bytes.
The generic collection-reader test stubs only asynchronous I/O and completion
notification; this is not an asynchronous game-load or rendering witness.

The native TXTR is 256x256 P8, six mips through 8x8, opaque neutral quilt art,

from the user's pinned retail helmet template, not a bundled retail binary.
Mip round trips reproduce the generated image; the base mip is lossless.
Native registration relocates both pixels and palette and returns the actual
descriptor used by the cap hook.

Common outer 3 has **224** retail chunks. Append `helmet01` as chunk 224 after
the final existing resource, retaining all 224 wrappers and every unowned byte.
The collection grows 2,387,424 to **2,475,968 bytes**. Its 544-byte alignment gap
is validated as padding and replaced through legitimate collection growth,
never treated as a resource slot. Sector-aligned pack growth is **88,064 bytes
(43 sectors)**. All 4,323 real index rows are checked: only outer 3's size and
the later virtual offsets change; pack counts 1..F remain identical.

The image writer resolves current XDVDFS and archive mappings. It preflights
both resource and executable states, optionally stages exact source-pinned
ROST selections, hashes the original pack, appends/reads back the replacement
in 1 MiB blocks, switches its existing node and invokes the established grown
XBE writer. No whole pack or image is read into a Python buffer. Ordinary
partial-write failures at pack data, pack node, XBE data, XBE node and same-size
XBE replacement restore the original nodes, executable, file length and whole
synthetic image hash. Handles close before publication/replacement. Power-loss
atomicity and concurrent external writers are not claimed.
