# DESIGN: phase 3 non-interactive lab for main

DESIGN: Main reviews and runs `bash pb/lab/pb_lab_def.sh`. Astra only checks syntax and source. This replaces the phase 2 operator procedure for this job. No operator command file, timed user reply, automated retry or second game is used.

DESIGN: Phase 4 replaces the isolated recipe with the real final draft plus only the three playbook overrides. QB Spy, screen D and the display-list fix remain enabled by production. Regenerate the copy with `python3 pb/recipes/compose.py <real-recipe> pb/lab/defense.recipe.json` whenever main changes the real recipe. The separate `pb/recipes/full_build.sh` is a build-only composition proof and never starts the lab.

DESIGN: The script builds one disposable disc from retail with all 64 packs through the same Ultimate recipe path. It then uses the shared u5 probe and r1 neutral-controller procedure for current Giants home versus Cowboys away, CPU versus CPU. `--minutes 8` is the intro-watch budget, not quarter length; game settings come from the isolated save. The shared route selects teams from observed menu text and presses LEFT once to leave the controller neutral. Main verifies that frame before interpreting results.

DESIGN: Build and runtime serialize on the shared lock. Runtime also waits until an existing xemu exits. Xemu runs only when main launches the script, at nice 19 on CPUs 24-31 with four Mesa threads. The shared route supplies a private configuration, 128 MiB RAM, loopback debugging and a COW HDD. Cleanup kills only the process group started by this script and removes its disposable ISO, overlay and RAM copies. Frames, build logs, watch JSON and stat JSON survive under the printed session directory. This script needs the read-only shared u5, k1 and r1 harness files at their documented paths.

DESIGN: Frames are requested every two seconds, OCR every twenty seconds, RAM copies at opening, every five minutes and at observed halftime/final/end. Captures can take longer than the requested interval. A separate process runs retail `0xCB240` over each RAM copy on CPUs 0-23, retains per-slot JSON and deletes that copy after successful extraction. No aggregate roster identity is guessed from fixed slots. Shared u5 RAM copies read a running process and are not atomic; use them for cumulative progress, not exact snap-aligned events. A static screen for 120 seconds stops and records evidence. Animated menu stalls need human review; no automatic button nudge hides them. A 4,200-second watch limit bounds the game. RAM or stats failures fail the run.

DESIGN: Main's review checklist:

1. Confirm the team-select and controller-neutral frames show current NYG home, DAL away and CPU control on both sides. Confirm one game and the build log's 64 pack applications and menu gate.
2. At several observable snaps on each defense, compare front alignment with the [NYG](../diagrams/NYG_defense.svg) and [DAL](../diagrams/DAL_defense.svg) pages: native personnel, interior spacing, edge width and the number of defenders at the line. Tite geometry over retail 4-3 personnel is a look, not a claim of true 3-4 personnel.
3. Count visible deep defenders before and after the snap. Separate a pre-snap two-high shell from a Cover 2/4/6 family. Look for corner-flat versus safety-flat rotations, robber depth, middle drop and native exchanges only when receiver/defender movement remains visible. Two-second sampling may miss the snap or transition; mark those samples unknown.
4. Count rushers and their starting positions. On replacement pressure, verify four rushers with an off-ball player rushing and a lineman dropping. On fire zone, verify five. Sacks, tackles and passing totals alone cannot prove blitz or coverage rates. Do not infer an invisible rusher from a sack.
5. Review every gap in the frame sequence. Confirm both sides repeatedly leave the play-call screen, line up, snap, finish plays and change possession. Compare passing/rushing attempts, yards and defensive stats across periodic native-stat receipts. A clock/animation continuing without new snaps is a possible play-call stall even if the static-screen detector does not fire.
6. Retain halftime/final frames, the final or watch-end stat receipt and any failure frame/log. Report each team independently as witnessed, incomplete or failed. A completed script, validator pass or advancing score is not sufficient evidence that every formation and coverage behaves correctly.

PROVED OFFLINE: The script has been syntax checked and the Python helpers compiled without importing or running the shared emulator probe. DESIGN: Gameplay, final-disc feature interactions, native exchange timing, pressure success and stall freedom remain for main to witness.
