## Built and decisions

The new `mod_editor/core/nfl2k5_practice_squad_screen.py`, generated byte
module, original `.S` and GNU-as assembler build an actual Coach's Desk
**Practice Squad** destination. The table keeps the four phase-specific
Schedule records first, Practice next, then Practice Squad, Front Office,
Gameplan, ESPN.com, Features, Options and Quit. The Crib's Coach's Desk row
is replaced. The independently pinned main-menu Crib row at `0x515528`,
callback `0x24D440`, and destination `0x524FA0` remain unchanged, preserving
its Trophy Room route. Controller navigation to that room is unwitnessed.

The brief's 728-byte menu allowance assumes an added action, while its actual
request replaces The Crib. Decision: reserve the full **728 bytes**, use
**12 action records + one terminator (676 bytes)**, and retain 52 zero padding
bytes after the terminator. Do not create a dummy action. The replacement is
taken from retail Crib row `0x52208C`, while the already-composed Schedule and
Free Practice records are copied from `0x521EEC`. Only the four-byte Coach's
Desk table pointer at `0x5221A0` changes in a retail section.

Clone Team Rosters descriptor `0x555098` (48 bytes), frame `0x555070`
(40), sheet `0x554C70` (320), and All Positions page `0x554B58` twice
(280 each). The two native pages are **Active** and **Reserves**, using
filter **17**, their own count/getters, and the existing NAME, POS and rating
columns. Both optional sort-key pointers at page `+0x94` are cleared. The
sheet's team selector and title use the captured human franchise context;
team cycling cannot silently switch the roster to another coach. Native tab
cycling, sorting and scrolling remain the spreadsheet's responsibility.
No search UI is added.

Activation uses the cloned sheet's `+0xC4` binding, retaining the native
`0x0003031D` argument descriptor: **ECX manager, EDX spreadsheet, stack row,
ret 4**. Resolve `spreadsheet->row_players[row]` at `+0x40`, bounded by
`+0xA4`, then open one action plus Cancel: **Demote** on Active, **Promote**
on Reserves. Revalidate context, membership and eligibility after the modal
dialog returns. A refused move shows a plain message and does not rebuild or
change roster/selection. No roster pointer is cached in persistent state.

Use exported `ps_promote = 0x3D1E20` and `ps_demote = 0x3DCBE8`, preserving
the shipped 53 active / 12 reserves / 65 physical slots rules, pointer
rotation, removal flags, special-team slot repair and salary recomputation
through `0xC3F00`, including its existing IR helper. Demotion additionally
clears the player's low five persistent-lock bits at `+0x52`, matching the
host transaction even when the optional depth-lock executable patch is off.
Ability bits stay intact. No global depth reranking or new salary-cap or
minimum-position approval dialog is introduced.

Rebuild after success with **native `0x174C70`**, clamp selection with native
`0x1707C0`, and clear stale scroll/row scratch. Empty lists are valid. Entry
uses event 1, departure uses event 5, and Back uses the native event-10 pop
record. Event hooks reset only the three owned state words. The ordinary
native constructor and destructor own the spreadsheet's heap arrays.

CPU poaching and protection are **off and unimplemented**, as the brief
permits unless cheap. The existing runtime prevents a different team from
promoting a reserve. Atomic cross-team moves, persistent protection metadata,
weekly scheduling and notifications need separate policy and save-version
work; this screen adds none of those fields or options.

## PROVED: guards, allocations and composition

Current context is `[0xE3C0A0]`, the value returned by retail `0x13EC80`.
Require franchise league type 1, a non-NULL ROST root and primary pool,
bounded root counts, an aligned NFL team object in that root, and that exact
object in the 34-entry league pointer array `0xE5786C` with nonzero human
ownership at `0xE5775C`. Never use the first-coach helper as a fallback.
The captured team must still match the live selected team on every page call
and action. A missing or switched context yields no rows/refuses the move.

Counts validate reserve version/count/marker, active+reserve capacity, NULL
reserve entries and zero unused tail through the fully pinned native
`reserve_count` helper. Its private compiled ABI is **EAX team**, not ECX.
Every exposed row must be a valid aligned primary pointer with exactly one
owner in the selected team. Bounded scans reject other active/reserve owners,
FA and franchise IR duplicates; retail all-star active aliases retain the
shipped exception. Negative/out-of-range rows, wrong selector/filter and NULL
players return zero. Move eligibility also rejects inactive/retired/prospect
flags and the IR marker, matching host preconditions.

The code and all immutable clones/strings consume **3,432 bytes**: **1,207
instruction bytes + 2,225 immutable/padding bytes**. The allocator request
reserves **4,096 RX bytes**, leaving 664 `CC` padding bytes, plus **256 RW
bytes** initially zero. Only 12 RW bytes are used (captured team, manager,
modal-busy flag). Immutable tables are included in the RX allowance, as in
existing owners; the budget has zero general-RO bytes. No runtime data is
placed in `.text`, no retail cave is claimed and no page count is changed.

A scratch copy of the committed budget table includes the three landed
beta-62 owners absent from its forecast rows. All **33 requests** fit:
50,800 RX bytes and 4,096 RW bytes remain available to future owners before
alignment; general RO availability is 13,312 bytes. The XBE is 12,300,288
bytes. `space.apply(..., scaleout=True)` realizes the union, and
`space.install_code` seals this owner's complete immutable payload.

`status`/`apply` recognize retail/prepared, applied and foreign/mixed bytes.
Exact replay returns identical bytes. Missing prerequisites or a sealed
allocation union without this owner refuse before mutation. Complete clone
sources and native ABI spans have literal SHA-256 pins; altered owner code,
tables, pointer, initial RW bytes, section digests or allocator seals refuse,
including after merely repinning section SHA-1.

The one prerequisite change is narrow: Franchise Practice's validator accepts
the delegated pointer only when this owner's exact sealed code/table validates,
while retaining every other original site check. Its `apply` preserves that
pointer on replay. Practice reserves, squads and Free Practice all still report
applied. No other core product behavior is changed.

The full owner union and both XBE gates include the screen, with forward and
reverse installation and byte-identical outputs. The cave-gate fixture now
explicitly requests v3 because the new union requires it. Its first run had
two failures from the documented stale legacy expectation of zero v3 raw
encodings. The unchanged v3 assertions require zero legacy encodings, no
retail mapping overlaps, 52 pages and the disclosed 1,081 raw candidates.
The known-red allocator scale-out/ordering suites were not edited.

## Bounded native proof scope

The Unicorn harness loads the real patched XBE and only the bounded extracted
ROST resource. It protects retail `.text` and maps every allocator page with
its declared permissions. Every call has a 3,000,000-instruction ceiling,
checks return/stack balance and preserves EBX/ESI/EDI/EBP.

**Actual native code executed:** event dispatcher `0x6E4E0`, screen handler
`0xF40F0`, frame walker `0x27CDF0`, constructor `0x1749D0`, count/getter and
activation argument expansion `0x172680/0x172930/0x1727F0`, rebuild
`0x1746C0/0x174140/0x174C70`, tab cycle `0x174CB0`, selection clamp,
spreadsheet destructor `0x1707F0/0x27C830`, Back pop `0x6E400`, new callbacks
and the shipped promote/demote/removal/salary routines.

**Harness boundaries:** heap allocation/free use bounded host services;
modal dialog and fade return selected results; cell formatting, cell styling
and geometry (`0x172660`, `0x1739F0`, `0x1701A0`) are stubbed. For the entry/
Back probe only, six menu-art/resource services (`0xF2920`, `0xF3CD0`,
`0xF3D60`, `0xF2D40`, `0xF3680`, `0xF3180`) are stubbed. The real constructor
allocates six buffers, and real teardown releases all six in the harness.
These bounds establish the callback/lifecycle ABI, not rendered text, fonts,
controller semantics, console heap pressure or a game witness.

Tests cover empty/1/12 reserves, active and reserve list dispatch, signed and
primary bounds, metadata corruption, other team/FA/IR duplicates, multiple
human coaches, sorted identity, 52/53 active and 11/12 reserve success/refusal,
65 total, last-row removal, cap recomputation versus host salary helpers,
contract preservation, special-team indices, lock/ability masks, Cancel,
ineligible players and ownership/tab/context changes during the modal dialog.
Page reads make only stack writes. Refused moves preserve roster bytes and
selection; success calls native rebuild and retains a legal final selection.
