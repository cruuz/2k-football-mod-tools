Branch: `astra/r65-back-throws`. Date: 2026-09-08.

The requested four-defect patch is **not implemented**. The brief permits

## Four cause sentences

These distinguish the observed code from a cause of the player's symptom.
None of the four symptoms has been reproduced through a complete game frame.

| Reported symptom | Cause sentence and evidence level |
| --- | --- |
| Pass behind a moving back | **HYPOTHESIS:** a prediction/movement mismatch at a turn or stopped/screen state could put the target behind the actual back, but **PROVED** native moving-route lead is already shared by HB, FB and WR, so a back-only missing-lead cause was not established. |
| Ball hits the helmet | **HYPOTHESIS:** the height-derived endpoint or the ball's earlier passage through the receiver could miss the live hands, but **PROVED** ordinary short targets are below the head and the above-head tap branch depends on field position, so helmet contact itself remains unproved. |
| Back makes no attempt | **HYPOTHESIS:** task entry, collision-mask eligibility or event timing may prevent a catch, but **PROVED** the release-time filter still permits a selected catch in the supplied counterexample and is not a universal no-attempt switch. |
| Needless dive/stumble and lost YAC | **HYPOTHESIS:** candidate eligibility or family/record priority could select an unsuitable motion, but the chosen motion's ground contact, a competing standing envelope and the subsequent YAC have not been proved, so no responsible dive-removal rule follows yet. |

### Target, body anchor and trajectory

`2DAF10` invokes target solver `2DA8E0`, accuracy routine `2D9700` and launch
routine `1CBDB0`. This call relationship is static evidence. The new probe
executes the complete `2DA8E0`, its route predictor and callees, `1CBDB0`, and
ball-position predictor `1CC820`; it does **not** execute all of `2DAF10` or
the accuracy pass.

* `2DA8E0` iterates flight time against predicted receiver position, up to
  seven times with the native 0.05-second convergence threshold. It reads
  native quarterback attributes and speed curves. It adds further lateral
  and downfield offsets after the iterative prediction.
* `2F43E0` adjusts the prediction horizon for throw strength, depth and lead
  input, clamps it to at least 0.6 seconds, and calls `2266A0`. That routine
  interpolates the supplied native route-prediction records. If prediction
  fails, `2F4350` uses the current clip's average root velocity, animation
  rate, player scale and facing. It is not simply a current-velocity read.
* The vertical anchor starts with roster height at `roster+2B`, multiplied
  by 2.54. The target is then adjusted by route kind, depth, field position
  and throw strength. It is **not** sampled from a live hand bone. The
  native catch selector separately evaluates animation hand positions.
* For the ordinary local cases tested, a 72-inch receiver gets target
  heights around 137-145 cm, not 182.88 cm. With local position `(200,200)`,
  lateral velocity `(500,0)` and tap strength zero, moving the line from
  `z=0` to `z=4500` changes the target from 145.16 to **208.28 cm**. This is
  a shared field-position-dependent branch, not proof that a swing in open
  field is aimed at a helmet.
* Route kinds 9/10 use current position in `2266A0`; kind 9 also changes
  height in `2F43E0`. The supplied moving kind-9 probe retains x=200 rather
  than leading x, and yields **27.432 / 82.296 / 137.16 cm** at strengths
  `0 / 0.5 / 1`. The existing `screen_receiver_chain` and `screen_endpoint`
  research identify kind 9 as a special screen endpoint. This is not the
  ordinary moving swing fixture, and it does not prove that the back is
  still moving when a retail screen uses this state.
* `1CBDB0` derives horizontal velocity from displacement / time and vertical
  velocity from height difference / time minus the native gravity term.
  Complete native `1CC820` evaluation reaches the selected target at that
  time. The supplied release height is 180 cm; the live quarterback hand
  pose and release animation are not reproduced.

HB, FB and WR fixtures have equal ratings, dimensions and route input, and
differ in the role/position fields. The 90 ordinary target/launch runs give
exactly equal target results across those three roles. This is a
controlled comparison, not a claim that actual rosters or animations match.
Unspecified object fields are zero; for example, the weight byte is zero,
not a captured real back's weight. Human/manual lead, pressure, fatigue
variation and post-target accuracy error remain separate work.

### Attempt, collision and final probability are different stages

The actual basic-block slice `2DB0F7..2DB1B7` reads the target's Catch
attribute through `17B010`, interpolates two native tables, clamps a value
to `[0.01,0.5]`, invokes the real RNG `48B90`, and may set
`target.state+8C & 0x800000`. Tests supply an explicit valid RNG ring; they
do not stub the RNG or attribute function. This is a slice of the release
routine, not a full throw-release replay.

Selectors `1E6600` and `1E38D0` use that bit to exclude records whose
`record+4C` is positive, unless a role-table flag exempts them. Native
`1E2660` establishes what that field means: it is the difference between
animation events **0x31 and 0x64**, when event 0x64 exists. Records without
that extra event still have event 0x31. Treating this as “all catch events
disabled” is incorrect. The role lookup uses 4-byte entries at
`509E08 + role*4`; the supplied HB/FB/WR entries have the same relevant bit.

With a supplied ball at `(0,137.16,100)` travelling `(0,0,-250)`, an origin
receiver, orientation bucket 0 and request type 0, full native `1E7410`
returns an accepted selection in **both** filter states, for all three roles:

| Filter bit | Selected record | Event gap | Native selector accepted |
| --- | --- | ---: | --- |
| Clear | `AB7F70`, animation `68BA90` | 0.532714844 s | Yes |
| Set | `AB79C0` | 0 s | Yes |

The complete 80-byte selection outputs also match across HB/FB/WR. This
counterexample defeats a blanket no-attempt interpretation of the filter.
It does not prove either motion is preferable or that possession follows.

`1C6100` builds a collision mask by running swept-sphere routine `1C52C0`
over 32-byte records. Tests execute that path with two deliberately supplied
volumes and show distinct masks and a miss. These are not claimed to be
captured helmet/hand collision volumes or proved names for joint bits.

`1E6360`, called by the native catch outcome path, checks **action descriptor
classes 5, 6 and 7**, not player positions 5, 6 and 7. Depending on record
flags it requires the appropriate collision bits, then rejects when
`abs(record.event_gap + state[E4] - state[08]) >= 0.15 seconds`. Complete
native calls prove both sides of this boundary and both mask branches for
HB, FB and WR. The delta is **event time, not stick magnitude**. Bypassing
it would permit physically mistimed contact, not prove a catchable pass.

The existing catch-slider hook in `1C78D0` at `1C8317` changes the final RNG
comparison through its header cave. That stage is downstream of candidate,
timing and collision checks. Raising its probability cannot alone prove that
an attempt is started or that a standing catch is chosen.

### Clip metadata and the remaining animation proof

`1E3070 -> 1E2890 -> 1E2660` initializes three catch candidate tables at
`ABE100`, `AC0E70` and `ABE830`, each with six orientation buckets. Records
are 112 bytes. Their retail stored tail fields are initially zero; using
those as runtime envelopes would be invalid.

The probe supplies the two shipped `lo_body/LO_res` hand-twist axes and
logical hand/parent indices, pinned by the existing
`tools/nfl_player_pose_native_validate.py`. With these inputs, the actual
native initializer makes **484 record initialization calls**. The three
tables enumerate **482 entries including aliases**, with two further fallback
records initialized outside them. All enumerated hand positions are finite.
For example, record `AB6290` refers to embedded animation `69AB24`, and its
computed hand y coordinate is 196.910 cm. Zeroing the hand-axis BSS instead
produces NaNs, an invalid fixture rather than a game defect.

`1E7410` can change the order of families A/B through `1E2C30`; it also
tries another family and fallback selection. Each family has eligibility,
orientation, geometry, timing and record-priority checks. A/B/C are address
labels here. They have **not** been proved to mean standing/jumping/diving.
Packed flag values and a low hand point alone do not establish a dive or
stumble, its recovery time, or whether another clip can catch the same ball.
No guessed flag was turned into a “keep upright” patch.

## Replay coverage

The CLI records 15 **supplied local motion segments**: swing right, swing
left, flat, angle and stationary checkdown, each at early/on_time/late
positions. Those timing labels describe fixture positions, not measured
release timestamps in an identified retail play. Strength is fixed at 0.5
and the supplied snap clock is 1.0 seconds. Direction is rotated both ways;
HB/FB/WR are compared at equal inputs. Position, velocity and numeric segment
kind are included in every receipt row.

The resulting **90 native target/launch runs** contain **4,872 native
ball-position samples** at up to 60 Hz. Maximum endpoint discrepancy from
the selected target is **0.0001220703125 cm**. These numbers prove the
component call chain and its arithmetic under the stated inputs.

## Noah's witness list and the missing implementation gate

Nothing in this session is witnessed gameplay. To turn this research into
the requested repair, the next native fixture needs a named retail play and
its loaded PLAY/ROST assignments through the real throw and catch tasks,
including active animation channels, event clocks and collision volumes.
The decisive before/after evidence must retain those inputs and RNG state.

Noah's playback matrix is the five requested geometries at early, on-time
and late release, mirrored across both sidelines and field directions:

1. Record team, playbook, formation, play, assignment, player, ratings,
   difficulty/sliders, release timing and tap/medium/held throw strength.
   Include halfbacks and fullbacks, then the closest WR control.
2. For a behind pass, record ball/receiver separation in route direction at
   actual contact and at the intended catch event; include route turns,
   stationary outlets, manual lead and a special screen as separate cases.
3. For helmet contact, retain the hand/head pose and ball path before the
   selected event. Include midfield and the high-tap field-position branch.
4. For no attempt, retain action-task transitions, the selected candidate,
   event delta, collision mask and final outcome RNG separately. Include
   human and CPU receivers and low/high Catch ratings.
5. For a needless fall, show the chosen motion, an eligible standing/running
   alternative at the same arrival point/time, ground-contact frames and
   yards after catch through touch-down. Include low, wide, late and
   contested balls that legitimately require a dive.
6. Once a real patch exists, repeat the identical seeds and plays with it
   off/on and with catch-slider, arc, coverage and momentum combinations.
   Require unchanged WR controls and retained necessary dives. Do not infer
   parity with 2K8 from a successful 2K5 byte patch or these component probes.

The full-frame fixture and the animation/envelope proof are outstanding
engineering work, not merely a request for Noah to approve an existing fix.
Until they establish a causal repair, this delivery remains research only.
