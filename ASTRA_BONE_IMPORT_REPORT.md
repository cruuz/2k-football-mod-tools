## PROVED: native interchange and output transport

The importable glTF contains only original primary-channel rotations at all
native frame times, including samples beyond the controller duration. It fixes
identity, name, frame/channel count, root duration, rate, multiplier and flags.
Nodes, accessors, samplers and buffer layout stay fixed; quaternion signs may
change. Derived joints are generated by the known family callbacks and cannot
be edited as independent tracks. The mandatory sidecar carries the original
whole resource, omission choices, original exporter hashes, events, trajectory,
auxiliary data, opaque fields and slack; it is checked against freshly read
source bytes, not authenticated against its own hash alone.

Unchanged and sign-equivalent keys reuse original packed words. The
`0x0319172a` non-largest-omission counterexample survives a glTF round trip.
Invalid unit quaternions, changed timing/layout, missing or foreign sidecars,
external buffers, duplicate JSON fields and failed pose comparisons refuse.
Arbitrary Blender re-export and general glTF graph rewriting are outside this
initial canonical interchange contract. It is not a skinned Blender control rig.

Each compiled request samples native frames and quarter/half/three-quarter
intervals, plus duration boundaries and repeated loops, under mirror/loop
combinations. It compares requested native interpolation against redecoded
output with a **0.75-degree** joint limit and actual float32 glTF time/slerp
samples with a **1.0-degree** joint limit. Packed changed keys retain the existing
**0.35-degree** encoding limit. These are discrete validation limits, not a
continuous error bound or a gameplay guarantee.

Both known archive seeds passed untouched glTF whole-span identity and one-key
edited comparisons. The referee gate compares 18,600 joint samples; the player
gate compares 37,400. Embedded comparisons retain the raw-channel/sign mirror
model; their real joint permutation and skeleton binding remain unresolved.
Unknown archive families do not arm UI/CLI import merely because channel counts
match a known skeleton.

The output-copy transport checks actual XDVDFS pack extents, the archive header,
outer identity/size, resource position, complete spans and overlap before writes.
The archive directory is also retained as an unchanged guard in the staged
transaction. It validates all members before the first write, including refusing
mixed original/applied members of a coordinated limb set. Split spans are checked
as one whole resource. Only exact differing byte runs are written.

The source copy and hashing use 1 MiB buffers. Source metadata and a second
streamed source hash catch changes, including filesystems that coalesce
modification timestamps. The staged output is read back and hashed. Every handle
closes before `os.replace`; outputs and adjacent receipts require new filenames.
Handled write/read-back/publication failures clean the staging directory and
owned output reservations. Existing outputs, aliases/hardlinks, foreign late
members, changed bundles and sources refuse. Replay writes zero actual changes.
Receipts distinguish compiled native changes from actual output write ranges and
include source/output hashes. No file or resource is silently resized.

**Decision:** SKEL `3/116` is included in the coordinated preflight and receipt,
but its **400-byte normalized axis array remains byte-identical**. It contains

**Decision:** recompute and report both meshes' actual min/max bounds, verify
all edited vertices still fit the original conservative native position bounds,
and retain those native encoding fields. Do not tighten bounds and requantize
unrelated vertices, or invent a writer for an unproved culling field. Head,
accessories and morph records retain their bytes. The inspector/exporter is not
being expanded into arbitrary body-profile or accessory authoring.
