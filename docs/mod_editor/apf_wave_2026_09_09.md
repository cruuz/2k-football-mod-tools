the pinned retail MASTER, including all 38 formerly unconverted opcode-1C

slot ordering and can edit all three alignment coordinate variants.

landmarks and stock assignment chains. Defensive man, zone and rush assignments
have offline codec/writer proof. A physical QB landmark is not proof of
five-step timing. Dedicated spy and five-step cadence remain hidden/deferred.

It rejects composition with Assignment Routes, Who lines up, independent

## Coverage Geometry

The opt-in panel lists all 368 shared opcode-0D nodes, four bounded knobs,
source defaults and every (play, slot, chain step) using the selected node.
Landmark X and drop depth are in feet; lateral/depth extents are in yards.

Composition starts at the pinned retail MASTER: coverage first, package maps
second, route clones third, then one outer-180 encode. The complete tuned
node pool must survive downstream edits. Shared-use previews are recomputed
from the final composed body. Mode/F/G bits and the non-geometry retail pin
remain protected. Base and TU decoder/consumer layouts are mapped. Receiver
carry, match decisions and gameplay quality are not proved by this writer.

## Book Identity and scheme presets

Every normal Build reparses its finished output into a 40-team / 80-assignment
Book Identity receipt. Labels and actual resources are separate identities.
The seven original offensive resources are shared across many labels.

Book Identity can stage Wide Zone (O-ZoneBlock), Spread-to-Run (O-Shotgun)
and Pro Power (O-ManBlock) in the normal project. Their existing plays and
formations, fallback rows and personnel fields remain bounded by the SPLB
writer. Current Fine-tune/Audible selectors compile first; a selected recipe
then owns membership and tags in its recipe records. The receipt records
both stages and their personnel availability. Revert the recipe to restore
the earlier selectors. Source changes and conflicting plans fail validation.

For independent offensive books, finish the complete-project Build first,
then use Book Identity → Choose built game folder → Independent offensive
book → Review change → Build new game folder. This is the LAST copy finalizer:
inserting sorted filename hashes changes outer ordinals. Its receipt contains
the old-to-new directory mapping. Do not feed a cloned archive back into the
retail-index authoring pipeline. Existing ROS files can override disc labels.
CPU clone consumption, WR depth order, true RPO and TU compatibility remain
unproved. No executable patch is required for book cloning.

## CPU Play Calling

Preview CPU audibles and personnel classifies MASTER flags and displays
before/after counts plus the 28-category supply table. Stage balanced CPU
audibles uses same-record TagMove selectors. A record without both a run
and pass is reported as impossible. A book with staged selectors or a staged
scheme recipe must be built or reverted before automatic balancing; other
books' edits survive. Normal Build receipts include personnel availability.
Empty/unreachable formation guards and secondary-mask regeneration warnings
remain enforced. Cross-formation audibles and CPU situation frequency are
not established by tag edits.

Export TE bias for pass fetches… defaults to **Choose game folder**. Select
the Xbox 360 folder containing `default.xex`. The studio reads your game's
executable, checks it is the retail BASE or Title Update 1.1, and writes a
Xenia patch file next to your build. It reads the update selected in the
studio's Xenia settings, or detects installed content in nearby `content`
folders and the configured Xenia content root. For an update installed
elsewhere, use **Choose Title Update 1.1…** and select its `TU_…` content file
or extracted `default.xexp`. A missing configured update, conflicting copies,
or an unknown update is refused rather than silently exporting a BASE patch.

After the check, the save dialog suggests a separate `.patch.toml` next to
your last build (or the selected game folder if you have not built yet).
BASE and TU have different suggested names and module hashes. The footer
names the detected version and saved path. A mismatch reports the SHA-256
it saw and both accepted image hashes. Your executable, update and game
packs are only read. Reading and unpacking runs in a background worker and
can take about a minute on a desktop CPU; its progress appears in the studio.

### What is a flat image

A flat image is the decrypted and decompressed executable inside
`default.xex`, laid out as the game loader would read it, before resolving
imports. It is a research representation of the executable, not a game
folder or the Title Update installer. You do not need to make one: the studio
derives it in memory from your own game and, when selected or detected,
applies the verified Title Update 1.1 delta there. It saves no decoded game
data. **Choose flat image (expert)** remains available for an already decoded
`.pe` file; both input choices use the same complete-image SHA check.
The shipped decoder is Python and needs no external executable, Java, or
native decryption/decompression package.

The experiment applies at every down, including user calls; the main
CPU weighted picker and its untyped emergency fetch remain unchanged.
Capstone 5.0.7 independently checks its instructions and branches.
Windows runtime construction pins its native wheel. Linux uses the configured
Python environment: install `capstone==5.0.7` alongside PyQt5 and Pillow there.
The installer reports a missing export dependency; ordinary book editing remains
available. Clean runtime/installer tests require all three dependencies, with
the user site disabled so it cannot hide an incomplete runtime.

The patch exclusively reserves **0x84D0E000..0x84D0EFFF** (a complete 4 KiB
page of .text padding); the emitted cave uses 716 bytes. The older franchise
example's broad claim 0x84D09100..0x84D0FFFF is split into
0x84D09100..0x84D0DFFF and 0x84D0F000..0x84D0FFFF. The intervening page
belongs only to this pass-fetch patch. Any external patch using that page
must be disabled before enabling this one. BASE module hash is
5447E5428AA2D52A; TU module hash is CEA825F7C2012F5A. Export status remains
UNWITNESSED, and no emulator is launched automatically.

## PS3 APFe texture bundles

Team Logo and Field Art expose Import PS3 bundle…. Review each semantic
logo_l0/logo_l1 or endzone_l0/endzone_l1 pair and its explicit Xbox destination.
DDS is preferred; GTF is decoded only when DDS is absent. Numeric PS3 entry
indices are not portable. Hash matches identify library slots, not team
ownership. Duplicate assignments and ambiguous variants fail closed.

The supplied bundle's offline inventory has 55 valid pairs; 46 hash-matched
writer-supported pairs comprise 27 crests and 19 endzones. Each complete
Build must still pass fixed-allocation checks. The importer preserves distinct
layers, session Undo/Revert and shared project payloads. Crest mip chains
regenerate and linked caches use the same paired art. Field Art keeps its
existing old mip tails; format-59 endzones remain read-only. Rendered palette
colors, cache consumption and Xenia appearance require a game witness.

PS3 roster inspection and the full-package texture comparison are read-only
diagnostics. A source roster's presence does not establish Xbox compatibility.
