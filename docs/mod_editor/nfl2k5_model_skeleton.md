# Player skeleton import for maumau78 (beta 66.1 H4)

The Models body-set importer accepts a bounded change to an exported player rest skeleton. Select **Geometry and skeleton**, keep `lo_body`, `hi_body`, `hi_head` and `player-body-set.skeleton.json` from one export together, and check either a body file or that folder. The writer preflights all four native resources, including SKEL, and publishes a new disc copy only after verification. Geometry only remains the default.

The supported operation is **one left or right forearm, thigh, shin or foot length, 95%–105% of its exported length**. Keep joint names and parents unchanged. Move bind translations along the original bone direction, retaining every other length. For a forearm, scale both elbow-to-wrist and wrist-to-hand offsets together. For a thigh, shin or foot, translate the distal chain by the endpoint displacement. Both body LODs must request the same primary positions. The high-only twist and muscle pivots may stay unedited: the importer regenerates them. Alternatively supply their exact generated positions. The head bind must stay unchanged.

In Blender, retain Custom Properties and mesh Attributes on export. Move each affected bone's head and tail together to preserve its orientation; changing the tail alone commonly changes a rotation and is refused. The native game uses centimetres; glTF uses a 0.01 unit root. Blender's world inverse binds and Models' mesh-space inverse binds are both accepted. Float conversion differences up to **0.001 cm** are snapped to the bounded canonical bind; serialized native binds are checked at **0.0001 cm**. Keep the mesh unstretched while editing the skeleton: the importer applies the coordinated axial mesh deformation and inverse-transpose normal adjustment. Independent geometry edits are fitted first, then carried with the limb change.

Upper arms are not enabled: the tested +1% and +5% edits could not fit the fixed compressed body allocation. Hand tips have no exported successor joint from which to derive a new tip length. Spine/neck/head coordination is not proved: the head has its own thorax-relative bind frame. Direction edits require a new proof of the fixed muscle graph, so this release refuses them. Multiple bone length changes in one import are also refused. These boundaries are intentional; this is not arbitrary armature replacement.

The exact one-LOD refusal is `edit both LOD files from one export`. Other refusals name joint topology, changed names, rotation/scale, animation, head coordination, derived pivot disagreement, source/export mismatch, the +/-5% bound, unsupported direction/multiple lengths, native vertex bounds, or a compressed span that cannot fit. There is no partial publication. A present but untouched second LOD is refused just as a missing LOD is.

The check receipt lists the requested bone's total length, each changed bind's parent-relative before/after length in cm, recomputed axis segments, decoded/compressed write ranges, refit accounting and the generated skeleton positions/parents. The current Models page has no 3D preview; its receipt shows the skeleton changes as text. `skeleton_overlay` is available in the receipt for a future renderer.

## Proof boundary

The starting facts are **PROVED**, from [the beta-66 report, section 9](../../ASTRA_B66_2K5_GAME_REPORT.md#9-maumau78-edited-gltf-skeleton-import): SCNE stride 112, absolute/local translations at +0x40/+0x50, name/parent at +0x60/+0x64; low/high counts 25/62; SKEL 3/116 is 25 normalized four-float direction vectors; 0x92140 loads SKEL and 0x92252 passes an axis to 0x90250. The existing forearm writer already coordinates translations, twists, mesh, normals and fixed-span recompression.

For the admitted axial operation, `normalize(s * v) = normalize(v)` for positive `s`. The importer recomputes every edited segment direction from the new low bind and checks it against the pinned SKEL float32 vector within 2e-6 per component. Canonical vector bytes are retained rather than perturbing their last bits. Thus 0x92140 receives the same rotations, axes and 351 constants at 0x4EF8E0, and computes the same angular muscle response. **That proves those constants need no change for this preserved-angular-response contract. It does not prove new direction edits or anatomically correct muscle behavior in gameplay.** Constants SHA-256: `e8c9a58a80d9531ecfb446d0c5350d5579fea1c1eea6fc47a2f802cdaa06129b`.

The extended native gate executes the pinned retail XBE's 0x92140 and 0x233C0. It maps the edited decoded SCNE records, relocates the shape bind pointer as the loader does, and captures the actual ECX axis argument at 0x92252. Identity-pose joint world positions are compared against the authored glTF targets. The recovered C graph and separate Python float32 graph are compared across identity and six samples of the existing player celebration clip. No executable bytes are patched by this writer. The original native gate still covers two compilers, UBSan and eight input cases.

Identity low rotations do not imply identity high-detail vertex skinning: the retail angular muscle graph already displaces some high vertices by 2.01620198 cm. This is reported separately from joint target error. Finite edited vertex skinning is checked across the sampled poses, but it is not an appearance certificate.

Synthetic and direct Models-export no-op imports retain every resource byte. Real Blender 4.0.2 roundtrips can re-encode geometry; byte identity is not claimed for Blender's regenerated meshes. Headless Blender +5% forearm/thigh edits are separately tested as GLB input. Compact disposable XISO transport checks the complete four-resource copy, replay, unchanged source, and refusal of a foreign head byte before publication. No retail disc image is built for this gate.

Idle/run/pass/catch/tackle poses, ball and helmet attachments, body sizes, collisions and visual quality are **UNWITNESSED**. The feature is EXPERIMENTAL, off by default. A metadata registry row, a headless Blender import and a native numerical gate are different evidence from playing the game.
